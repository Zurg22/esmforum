\# Planejamento Ágil — ESM Forum



\## 1. Metodologia escolhida



Para o desenvolvimento das novas funcionalidades do ESM Forum foi escolhido o Scrum.



O Scrum foi escolhido porque o projeto possui um conjunto definido de funcionalidades que podem ser divididas em pequenas entregas. A utilização de um backlog priorizado permite organizar o desenvolvimento de acordo com a importância de cada funcionalidade.



Além disso, o Scrum permite acompanhar a evolução do trabalho por meio de tarefas menores e ciclos de desenvolvimento, facilitando o acompanhamento do progresso das funcionalidades.



\## 2. Backlog de funcionalidades



Foram definidas cinco funcionalidades principais para evolução do ESM Forum:



1\. Votação em perguntas

2\. Busca de perguntas por palavra-chave

3\. Categorização e tags

4\. Perfil do usuário com histórico

5\. Notificações de novas respostas



\## 3. Funcionalidades planejadas



\### 1. Votação em perguntas



Permitir que os usuários possam votar positivamente ou negativamente nas perguntas publicadas no fórum.



Objetivo:



\* permitir que a comunidade demonstre quais perguntas são mais relevantes;

\* facilitar a identificação das perguntas com maior interesse.



Prioridade: Alta.



\### 2. Busca de perguntas por palavra-chave



Permitir que o usuário pesquise perguntas utilizando palavras-chave.



Objetivo:



\* facilitar a localização de perguntas existentes;

\* evitar a necessidade de procurar manualmente entre todas as perguntas cadastradas.



Prioridade: Alta.



\### 3. Categorização e tags



Permitir a classificação das perguntas por categorias e tags, como:



\* Tecnologia

\* Carreira

\* Dúvidas gerais



Objetivo:



\* organizar o conteúdo do fórum;

\* facilitar a navegação e a localização de assuntos relacionados.



Prioridade: Média.



\### 4. Perfil do usuário com histórico



Criar uma área de perfil na qual o usuário possa consultar suas perguntas e respostas anteriores.



Objetivo:



\* permitir que o usuário acompanhe sua participação no fórum;

\* facilitar o acesso ao histórico de contribuições.



Prioridade: Média.



\### 5. Notificações de novas respostas



Permitir que o usuário receba uma notificação quando uma nova resposta for publicada em uma pergunta criada por ele.



Objetivo:



\* informar o autor sobre novas interações;

\* facilitar o acompanhamento das perguntas publicadas.



Prioridade: Média.



\## 4. Priorização



A priorização inicial do backlog foi definida considerando o impacto de cada funcionalidade na utilização do fórum.



| Prioridade | Funcionalidade                  | Justificativa                                                               |

| ---------- | ------------------------------- | --------------------------------------------------------------------------- |

| 1          | Votação em perguntas            | Permite identificar a relevância das perguntas pela interação dos usuários. |

| 2          | Busca por palavra-chave         | Facilita o acesso ao conteúdo existente no fórum.                           |

| 3          | Categorização e tags            | Melhora a organização das perguntas.                                        |

| 4          | Perfil com histórico            | Permite acompanhar as próprias contribuições.                               |

| 5          | Notificações de novas respostas | Melhora o acompanhamento das interações nas perguntas.                      |



A ordem representa a sequência inicial de prioridade do backlog e pode ser ajustada conforme o andamento do projeto e as necessidades identificadas durante o desenvolvimento.



\## 5. Organização no GitHub Projects



As cinco funcionalidades serão representadas como itens no GitHub Projects.



Cada funcionalidade deverá ser acompanhada como uma tarefa independente, permitindo visualizar seu estado durante o desenvolvimento.



A organização planejada será:



\* Backlog / To Do

\* Em andamento / In Progress

\* Concluído / Done



As funcionalidades inicialmente permanecerão no backlog e serão movidas para desenvolvimento conforme a prioridade definida.



\## 6. Acompanhamento



O progresso do projeto será acompanhado pelo GitHub Projects.



A cada evolução de uma funcionalidade, seu cartão deverá ser atualizado para representar seu estado atual.



Dessa forma, o quadro permitirá visualizar quais funcionalidades ainda estão aguardando desenvolvimento, quais estão em desenvolvimento e quais já foram concluídas.
